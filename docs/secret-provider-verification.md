# GitHub·AWS 실제 연결 확인

실제 원천의 키를 시험 저장소에 복사하거나 원문을 DB에 넣지 않는다. 기존 합성 시험은 공급자 인증을 호출하지 않는다. 아래 두 확인 범위를 구분한다.

## AWS 읽기 어댑터 확인

운영자가 승인한 로컬 프로필만 메모리에서 읽어 실제 STS 인증과 같은 주체의 IAM 정책 조회를 확인한다. 수집 원천·발견 키·검증 이력·권한 근거를 DB에 만들지 않는다. 키 생성·변경·폐기나 정책 변경도 수행하지 않는다.

Windows PowerShell에서 Java 21을 선택한 뒤 실행한다.

```powershell
$env:SECRET_LIVE_AWS_PERMISSION_VERIFY = 'true'
$env:SECRET_LIVE_AWS_PROFILE = 'new' # 승인한 읽기 계정의 명시적 프로필
./gradlew.bat --no-daemon :secret-worker:test --tests '*AwsPermissionLiveVerificationTest' --console=plain
Remove-Item Env:SECRET_LIVE_AWS_PERMISSION_VERIFY
Remove-Item Env:SECRET_LIVE_AWS_PROFILE
```

기본 시험·CI에서는 이 시험을 건너뛴다. 실행 결과에는 비밀 원문, 계정 번호, 사용자 ARN, 정책 원문을 출력하지 않는다. IAM 조회 권한이 없거나 연결된 정책에서 지원 capability를 찾지 못하면 성공으로 표시하지 않는다. 성공도 발견한 특정 키에 대한 검증·권한 확정 완료를 의미하지 않는다.

## 발견 키부터 담당자 확정까지

1. 승인된 실제 시험 원천에 원래 존재하는 폐기 가능한 최소 권한 시험 키를 사용한다. 기존 합성 fixture나 수집용 GitHub App 권한을 발견 키의 권한으로 대신하지 않는다.
2. 탐지 목록에서 키 상세와 발견 위치를 선택한다. 해당 위치의 현재 승인·수집 연결과 키 구성을 확인한다.
3. 키 유효성 확인을 명시적으로 요청한다. 새 검증이 실제 인증에 성공하여 현재 주체 연결을 기록해야 한다. 과거 VALID 기록만으로 새 주체를 만들어내지 않는다.
4. `키 권한 확인`에서 현재 조건을 조회한다. 신원 확인 전 조회 연결은 '아직 판별할 수 없음'이며, 같은 계정/원천의 승인 연결을 실제로 대조한 뒤 부족 여부를 표시한다.
5. 권한 정보를 가져온다. 자동 수집 자료는 후보이며 정책 조회만으로 전체 유효 권한이나 심각도를 확정하지 않는다.
6. 담당자가 실제 검증·자산 분류·권한과 제한 조건 조사 자료를 검토하고 확인한 자료만 확정한다. 부족한 근거·만료·변경이 있으면 보완 또는 재수집한다.
7. 기존 v2 정책의 평가 결과·적용 규칙·변경 이력을 확인한다. 후보 수집 자체가 등급을 변경하지 않는지 함께 확인한다.

실제 시험 키와 승인된 원천이 없으면 전체 실제 연결 시험은 미완료로 남긴다. 격리 DB의 모의 HTTP·합성 확인 시험은 그 상태를 대신하지 않는다. 기본 평가 정책(v2)과 720개 신규 정책 보류 결정은 유지한다.
