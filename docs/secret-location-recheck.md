# 조치 후 발견 위치 재검사

이 검사는 원래 키가 조치한 위치에 남아 있는지 확인한다. 키 자체의 인증 가능성을 검사하는 `REVALIDATE/CREDENTIAL_VALIDITY`와 별개인 `REVALIDATE/LOCATION_RECHECK` 작업이다. 원천은 읽기만 하며 키·자원·권한을 변경하지 않는다.

## 지원 원천

- 승인된 GitHub 현재 커밋 파일.
- 정확히 승인된 AWS Secrets Manager 현재 텍스트 값, SSM Parameter 현재 값, S3 객체 현재 UTF-8 값.
- IAM 접근키 목록과 Secrets Manager·SSM·S3 목록 메타데이터는 대상이 아니다.

기존 대응 건의 담당자 권한·조치 기록·조치 마침·현재 승인 범위를 충족한 뒤, 기존 위치별 재검사 명령을 사용한다. 건 단위 호환 API는 `POST /api/v1/secrets/cases/{caseId}/revalidations`다. UI는 서버의 `canRequestRevalidation`과 차단 사유를 따른다.

## 결과 해석

| 상태 | 근거 |
|---|---|
| PRESENT | 비교 가능한 현재 값에서 원래 키를 다시 발견 |
| MISSING | 승인된 현재 값을 성공적으로 읽고 필수 탐지·정규화를 완결했으며 원래 키가 없음 |
| UNKNOWN | 읽기 실패·NotFound·승인/원천/신원 변경·리스 상실·탐지 불확실·불완전 후보 등으로 제거를 입증하지 못함 |

같은 키 HMAC·보호키 버전·위치·scope revision·출처 버전·조치 cycle·조치 이후 시각을 확인한다. 작업 리스를 잃은 워커는 결과를 게시하지 못한다. 값 안에 다른 키가 생겨도 새 키를 원래 키로 대신 검증하지 않는다. 해석하지 못한 탐지 후보는 `DETECTOR_NORMALIZATION_INCOMPLETE`로 남기며 정상 미발견으로 처리하지 않는다.

AWS 자원 자체의 삭제/NotFound는 현재 어댑터에서 독립 삭제 증명으로 사용하지 않으므로 UNKNOWN이다. 성공적으로 읽은 값에서 원래 키를 제거·교체한 경우와 구분한다. 원천 미발견은 공급자 키의 폐기·만료 증명이 아니다.

후속 전체 스캔·승인 변경 등으로 비교 기준이 달라지면 예전 미발견을 현재 해결 근거로 쓰지 않는다. 위치 상태의 근거 표시와 건 전체 해결 검사는 같은 최신 실행 조건을 사용한다. 모든 필수 위치·검사 범위·별도 수명주기 증거가 충족되어야 기존 해결 검사를 통과한다.
