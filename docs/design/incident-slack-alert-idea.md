# 보안 사고 신호 Slack 알림 (아이디어)

- 상태: **아이디어, 개발 예정.** 아직 만들지 않았고 설계도 확정하지 않았다. 지금 바로 쓰지 않는다.
- 관련: 사용법 도우미 챗봇 설계 문서(develop의 `docs/design/usage-chatbot-design.md`) 16장. 챗봇 패널 안의 "새 보안 신호" 알림은 develop에 이미 반영되어 있다.

## 하려는 것
대시보드를 열어 두지 않은 담당자에게도, 아래 네 가지 신호가 생기면 보안 담당 Slack 채널로 알린다. 챗봇 패널 알림은 탭을 열어 둔 사람만 볼 수 있다는 한계가 있어서다.

| 신호 | 뜻 |
| --- | --- |
| 새 런타임 탐지 | 의심스러운 시도. 검토 안 한 런타임 탐지가 늘었다 |
| 활발한 키 | 유효(VALID)한 키 대응 건이나 실키 경고가 늘었다 |
| 센서 꺼짐 | 정상 런타임 센서가 줄어 침해 흔적을 볼 수 없다 |
| 위험한 노출 증가 | 실행 중+도달 가능 Critical·High, 1순위 공격 경로, 드리프트가 늘었다 |

## 지킬 원칙
- Slack으로 나가는 것은 **신호 종류, 늘어난 숫자, Logssey 화면 링크뿐**이다. 키 값·키 이름·발견 위치·워크로드 이름·로그 원문은 보내지 않는다.
- AI를 쓰지 않는다.
- 같은 신호를 반복해서 보내지 않도록 묶어서, 늘었을 때만 보낸다.
- 기본은 꺼 두고, 켜지 않으면 다른 기능에 영향이 없다.

## 만들기 전에 정할 것
- 백엔드가 런타임·시크릿·IaC·취약점 데이터를 읽어야 하므로 **각 모듈 담당자 승인**
- 사용자 없이 도는 작업이라 시크릿 모듈의 접근 범위 정책과 맞는지 (시크릿 담당 확인)
- Slack 웹훅 주소를 어디에 보관할지 (시크릿 매니저)
- 알림 채널, 보내는 주기
