# Secret inventory API

Inventory and detail reads require an authenticated dashboard user with current Secret `SECURITY` or assigned `REMEDIATOR` access. Live location ACLs apply before grouping, counts, and result projection; `OPERATIONS` alone does not grant credential inventory access. The connection picker requires `OPERATIONS` for the returned connection. Responses use `secret_credential_sets` and `secret_occurrences`; the legacy `credentials` table is not queried.

- `GET /api/v1/secrets?page=0&size=20&issuer=ALL&componentState=ALL` returns page fields `{items,total,page,size}` plus snapshot metadata. Page is zero-based; size is 1-100. Issuer can be `ALL`, `AWS`, `GITHUB`, `NOTION`, or `KUBERNETES`; component state can be `ALL`, `CONFIRMED`, `CANDIDATE`, or `METADATA_ONLY`. The default origin is `PRODUCTION` and content kind is `VALUE_FINDINGS`; use `contentKind=METADATA` for metadata entries. Results order by remediation priority, then ID. The controller also accepts the current source/provider, environment, work-bucket, validity, severity, snapshot, and run filters.
- Each item includes `id`, `issuer`, `credentialType`, `componentState`, `maskedLabel`, `severity`, `validationStatus`, `validationReasonCode`, `validatedAt`, `validationCheckedAt`, `occurrenceCount`, `firstSeenAt`, and `lastSeenAt`. Severity summarizes the highest effective stored grade among relevant visible locations. Read `assessmentStatus`, `effectiveSeverity`, `unassessedOccurrenceCount`, and `heldOccurrenceCount` together: missing assessment remains `UNASSESSED`, assessment outside scope can be `NOT_APPLICABLE` with null severity, and a recorded held application can remain effective while new evidence is unassessed.
- Validation fields derive from currently eligible `COMPLETED` location evidence, with current credential, scope, validation, and approval revisions checked. Reservations, unfinished attempts, legacy evidence without current eligibility, and revoked or outdated approval contexts do not become the current result. Without eligible evidence, the status is `UNCHECKED` and reason/timestamps can be null. Both `validatedAt` and `validationCheckedAt` are provider observation time (`provider_checked_at`), not attempt completion; they remain null when no provider response was observed. A material action can require a new check and project `UNCHECKED/POST_ACTION_VALIDATION_REQUIRED`. Unknown stored reason codes are reported as `UNSPECIFIED_REASON`.
- `GET /api/v1/secrets/{id}` adds `expiryPolicy`, `expiresAt`, `lifecycleStatus`, and visible `occurrences`. Occurrences include connection, environment, exposure, presence, and observation fields. Compatibility `sourceObjectRef` is a safe location label and `locationKey` is null; authorized source details have their own safe projection. Unknown environment remains `UNKNOWN`. Separate locations of one confirmed credential remain separate occurrence entries; candidates remain separate credential sets.
- `GET /api/v1/secrets/connections` returns `{items:[{connectionId,provider,displayName,status,approvedScopeCount}]}` for authorized active `GITHUB` and supported `AWS` connections with enabled approved scopes. AWS requires a valid approved AWS profile reference and supported scopes. Manual scans support GitHub and AWS metadata or approved exact-value scopes; execution also requires the corresponding worker opt-ins. Unsupported providers or scope configurations are rejected by run registration with 409.

For a selected location, `GET /api/v1/secrets/{id}/validation?occurrenceId=...` separates the latest completed attempt, last authenticated time, last conclusive validation, pending request, and freshness. `POST /api/v1/secrets/{id}/validation-requests` accepts only `{occurrenceId,expectedContextVersion,idempotencyKey}` and returns 202 with a request ID; acceptance is not authentication success. Request status, history, and scope-policy routes are defined in the [credential validation controller](../src/main/java/com/logssey/secret/validation/SecretValidationController.java). See the [worker operating guide](../secret-worker/README.md) for default-disabled provider flags, connection-profile registration, scope approval, and runtime limits. Collection success and connection probes do not authenticate a discovered key.

No endpoint returns credential fingerprints, candidate locators, credential components, authentication references, raw approved scope references, detector raw output, or full provider responses. `/api/v1/credentials` remains available during the agreed migration period.
