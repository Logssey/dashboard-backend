# Secret inventory API (MVP)

All three routes require an authenticated dashboard user whose current `dashboard_users.role` is `ADMIN`. This is a temporary boundary until Secret-specific grants are implemented. Responses use the V4 `secret_credential_sets` and `secret_occurrences` tables; the legacy `credentials` table is not queried.

- `GET /api/v1/secrets?page=0&size=20&issuer=ALL&componentState=ALL` returns `{items,total,page,size}`. Page is zero-based; size is 1–100. Issuer can be `ALL`, `AWS`, `GITHUB`, `NOTION`, or `KUBERNETES`; component state can be `ALL`, `CONFIRMED`, `CANDIDATE`, or `METADATA_ONLY`. Results order by most recently seen, then ID.
- Each item has `id`, `issuer`, `credentialType`, `componentState`, `maskedLabel`, `severity`, `validationStatus`, `validationReasonCode`, `validatedAt`, `validationCheckedAt`, `occurrenceCount`, `firstSeenAt`, and `lastSeenAt`. `severity` is `UNASSESSED` until a supported assessment policy exists. The latest completed validation attempt supplies the validation fields; without an attempt, the status is `UNCHECKED` and the reason and timestamps are null. `validatedAt` is attempt completion; `validationCheckedAt` is the provider check time, which can be null when no provider call occurred. Unknown stored reason codes are reported as `UNSPECIFIED_REASON`.
- `GET /api/v1/secrets/{id}` adds `expiryPolicy`, `expiresAt`, `lifecycleStatus`, and `occurrences`. Each occurrence has `id`, `connectionId`, `sourceObjectRef`, `locationKey`, `environment`, `exposureStatus`, `exposureRange`, `presenceStatus`, `firstSeenAt`, and `lastSeenAt`. Unknown environment remains `UNKNOWN`. Separate locations of one confirmed credential are separate occurrence entries; candidates remain separate credential sets.
- `GET /api/v1/secrets/connections` returns `{items:[{connectionId,provider,displayName,status,approvedScopeCount}]}` for active GitHub connections with at least one enabled approved scope. Only GitHub scans are executable in this MVP; other providers do not appear in the picker and `POST /api/v1/secrets/runs` rejects them with 409 until their worker pipeline is implemented.

No endpoint returns fingerprints, candidate locators, credential components, external key references, authorization references, approved scope references, or detector raw output. `/api/v1/credentials` remains available during the agreed migration period.
