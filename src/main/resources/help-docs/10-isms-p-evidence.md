# ISMS-P 항목별로 Logssey에서 증적을 보는 곳

ISMS-P(정보보호 및 개인정보보호 관리체계 인증, 2023 기준 101개 항목)의 항목마다, 관련된 기술적 증적을 Logssey 어느 화면에서 볼 수 있는지 정리했습니다. 항목 번호와 이름은 컴플라이언스 화면의 ISMS-P 보고서와 같습니다.

## 먼저 알아 둘 것
- Logssey는 기술적 증적의 일부만 보여 줍니다. 항목을 갖췄는지와 인증 여부는 심사원이 문서, 절차, 인터뷰를 함께 보고 판단합니다.
- 그래서 이 안내는 "이 항목과 관련된 증적을 이 화면에서 볼 수 있다"까지만 말합니다. 갖췄다거나 인증이 된다고 단정하지 않습니다.
- Logssey가 볼 수 있는 데이터가 없는 항목은 "Logssey 밖"으로 적었습니다. 담당 부서의 문서, 절차, 기록으로 증명합니다.
- 도우미는 실제 점검 결과를 볼 수 없습니다. 결과와 숫자는 각 화면에서 직접 확인하세요.

## 항목별로 Logssey에서 볼 곳
아래 항목은 컴플라이언스 보고서 말고도 Logssey 다른 화면에 관련 증적이 있습니다.

### 2.5.1 사용자 계정 관리, 2.5.2 사용자 식별, 2.5.3 사용자 인증, 2.5.4 비밀번호 관리, 2.5.5 특수 계정 및 권한 관리, 2.5.6 접근권한 검토
- Logssey에서 볼 곳: 컴플라이언스의 "ISMS-P" 보고서.
- 무엇을 보면 되나: 해당 항목의 AWS 계정·인증·권한 점검 결과.
- 한계: AWS 계정 범위만 봅니다. Logssey 자체 로그인 계정 관리 기록은 아닙니다.

### 2.6.1 네트워크 접근
- Logssey에서 볼 곳: 컴플라이언스의 "ISMS-P" 보고서, 인프라 보안 > IaC 보안의 "지금 열린 공격 경로".
- 무엇을 보면 되나: 바깥에서 닿는 경로가 열려 있는지.
- 한계: 클라우드 네트워크 설정만 봅니다.

### 2.7.1 암호정책 적용
- Logssey에서 볼 곳: 컴플라이언스의 "ISMS-P" 보고서.
- 무엇을 보면 되나: AWS 저장소·전송 암호화 점검 결과.

### 2.7.2 암호키 관리
- Logssey에서 볼 곳: 시크릿의 "키·노출 위치"와 "대응 관리", IaC 보안의 "State 속 실제 시크릿", 컴플라이언스.
- 무엇을 보면 되나: 코드·설정에 노출된 키를 찾아 대응 건으로 교체·종료한 기록.
- 한계: 키를 만들고 보관하는 절차 문서는 Logssey 밖입니다.

### 2.8.5 소스 프로그램 관리
- Logssey에서 볼 곳: 시크릿의 "키·노출 위치"(저장소 스캔)와 "스캔 이력".
- 무엇을 보면 되나: 소스 저장소에 키가 노출됐는지와 스캔 이력.
- 한계: 소스 접근 권한과 변경 이력 관리 절차는 Logssey 밖입니다.

### 2.9.1 변경관리
- Logssey에서 볼 곳: 인프라 보안 > IaC 보안의 "실제 드리프트".
- 무엇을 보면 되나: 코드와 다르게 바뀐 클라우드 설정이 있는지.
- 한계: 변경 승인 절차는 Logssey 밖입니다. 이 항목은 컴플라이언스 보고서에서 수동 항목입니다.

### 2.9.4 로그 및 접속기록 관리
- Logssey에서 볼 곳: 컴플라이언스의 "ISMS-P" 보고서.
- 무엇을 보면 되나: AWS 로그 설정(감사 로그 등) 점검 결과.
- 한계: Logssey 자체 로그인 기록 보관은 아닙니다.

### 2.10.1 보안시스템 운영
- Logssey에서 볼 곳: 인프라 보안 > 런타임 보안의 "Sensor 상태", 컴플라이언스.
- 무엇을 보면 되나: 탐지 센서가 정상으로 돌고 있는지.

### 2.10.2 클라우드 보안
- Logssey에서 볼 곳: 컴플라이언스, IaC 보안의 "지금 열린 공격 경로"와 "실제 드리프트".
- 무엇을 보면 되나: 클라우드 설정 점검 결과와 열린 경로.

### 2.10.8 패치관리
- Logssey에서 볼 곳: 취약점 관리 Finding 상세의 "수정 버전"과 "업그레이드 제안", 스캔 화면의 새 스캔, 컴플라이언스.
- 무엇을 보면 되나: 실행 중 이미지의 취약 패키지가 수정 버전으로 바뀌고 새 스캔에서 사라졌는지.
- 한계: 운영체제 패치 절차는 Logssey 밖입니다.

### 2.10.9 악성코드 통제
- Logssey에서 볼 곳: 인프라 보안 > 런타임 보안의 "탐지 결과", 컴플라이언스.
- 무엇을 보면 되나: 이상한 프로그램 실행 탐지와 그 검토.
- 한계: 백신 운영은 Logssey 밖입니다.

### 2.11.1 사고 예방 및 대응체계 구축
- Logssey에서 볼 곳: 사용법 도우미의 "사고 대응 체크리스트" 버튼, 시크릿의 "대응 관리", 컴플라이언스.
- 무엇을 보면 되나: 사고 때 확인 순서와 대응 건 운영.
- 한계: 대응 조직과 절차 문서는 Logssey 밖입니다.

### 2.11.2 취약점 점검 및 조치
- Logssey에서 볼 곳: 취약점 관리(스캔, 워크로드의 "스캔 없음 · 불일치", Finding의 "검토 저장"), 시크릿 스캔, 컴플라이언스.
- 무엇을 보면 되나: 정기 스캔, 스캔이 빠진 곳, 검토·조치 기록.
- 한계: 모의해킹 같은 외부 점검은 Logssey 밖입니다.

### 2.11.3 이상행위 분석 및 모니터링
- Logssey에서 볼 곳: 인프라 보안 > 런타임 보안의 "탐지 결과", 사용법 도우미의 "새 보안 신호", 컴플라이언스.
- 무엇을 보면 되나: 검토하지 않은 탐지와 검토 기록.
- 한계: 센서가 없는 곳은 볼 수 없습니다.

### 2.11.5 사고 대응 및 복구
- Logssey에서 볼 곳: 시크릿의 "대응 관리", Finding의 판정·메모와 "검토 저장", 사용법 도우미의 "보고서 초안" 버튼.
- 무엇을 보면 되나: 사고 뒤 조치와 기록이 남았는지.
- 한계: 외부 신고와 복구 절차는 Logssey 밖입니다. 담당 부서와 확인하세요. 이 항목은 컴플라이언스 보고서에서 수동 항목입니다.

### 2.12.1 재해·재난 대비 안전조치, 2.12.2 재해 복구 시험 및 개선
- Logssey에서 볼 곳: 컴플라이언스의 "ISMS-P" 보고서.
- 무엇을 보면 되나: AWS 백업·복구 설정 점검 결과.
- 한계: 복구 훈련은 Logssey 밖입니다.

## 이런 질문에 답할 때
- "ISMS-P 2.11.2는 어디서 증적을 봐요?": 위 항목별 표에서 볼 곳과 확인할 것을 안내하고, 판단은 심사원이 한다고 덧붙입니다.
- "우리 ISMS-P 통과할 수 있어?", "몇 개 항목을 갖췄어?": 도우미는 실제 결과를 볼 수 없어서 답할 수 없습니다. 컴플라이언스 "ISMS-P" 보고서에서 직접 확인하고, 인증 여부는 심사원이 판단한다고 안내합니다.
